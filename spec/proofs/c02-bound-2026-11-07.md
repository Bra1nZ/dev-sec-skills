# C-02 bounded cross-check — declared bound

Date: 2026-11-07. Target: craft-i18n at
`5c5c55400e8f7f4ee4f64a64dc196335a6a1f256`.
Model: [`crosscheck/c02-row-model/src/model.rs`](../../crosscheck/c02-row-model/src/model.rs).
Comparison: [`crosscheck/c02-row-model/src/main.rs`](../../crosscheck/c02-row-model/src/main.rs).

This file fixes what the cross-check is allowed to claim **before** the run
that produced [`runs/c02-crosscheck-2026-11-07.json`](runs/c02-crosscheck-2026-11-07.json)
and [`runs/c02-mutants-2026-11-07.json`](runs/c02-mutants-2026-11-07.json).
The generator and the vocabulary were fixed before any recorded run. Two
unrecorded development invocations printed the same space size and zero
divergences; they are not evidence and are not cited. The recorded runs are the
ones under `runs/`.

## What is compared

Two implementations of the same question: for one catalog text and one plural
form count, which rows load, and which line numbers are rejected.

- The model is derived from `docs/catalog-format.md` in the target and the C-02
  claim (*a malformed row is rejected, a valid one still loads*). It is a second
  implementation, not a translation of `crates/craft-i18n-tests/src/catalog.rs`.
  Its rule-by-rule reading, including the rules the format document leaves
  implicit, is written at the top of `model.rs`.
- The implementation is called as a library:
  `craft_i18n_tests::catalog::read_catalog(text, forms)`.

A case agrees when both return the same accepted rows — `(line, context,
source, translation)` after unescaping — and the same list of rejected line
numbers. The implementation's problem **text** is not compared: the claim is
that a row is rejected, not that a particular sentence is printed. The
cross-check parses `line N:` only to recover `N`; an unparseable problem is
itself a divergence.

## The space

The space is enumerated, not sampled. There is no random generator, no clock
and no network. For a fixed binary and a fixed target checkout the enumeration
is identical on every machine.

1. **Single rows.** The full cross product of 10 context tokens, 30 source
   tokens and 25 translation tokens (7,500 rows). The tokens exercise empty
   fields, every reserved and unknown `@` context, placeholders in both orders,
   adjacent and unclosed placeholders, all three valid escapes plus an unknown
   one and a trailing backslash, the trailing `…`, plural forms, a literal
   control character, a carriage return inside a field, and a BOM inside a
   field.
2. **Column arity.** Every tuple of 0 to 4 columns over 8 column tokens, plus
   three 5-column rows. This covers wrong column counts without enumerating
   arbitrary text.
3. **Sequences.** Every ordered pair of 19 rule-shaped lines (361 pairs) and
   every ordered triple of 11 of them (1,331 triples). This is where the
   duplicate key, the "bad row is left out" rule and the line number of a
   rejected row after a blank or comment line are compared.
4. **Plural counts.** 7 plural sources × 7 plural translations × `forms` in
   {1, 2, 3}.
5. **File wrappers.** Each logical input is run five ways: plain, leading BOM,
   CRLF with a final newline, leading BOM + CRLF, and a final LF. This is the
   only place where file-level BOM and line-ending handling are compared.

**Declared ceiling:** at most 100,000 unique inputs, each at most 256 bytes.
The binary asserts both: an input above 256 bytes or a space above 100,000
inputs aborts the run, so a later vocabulary edit cannot silently grow the
bound. The actual size is printed by the run and recorded in its log; the
ceiling is a declaration, not a guess about the actual size.

**Measured size before the recorded run:** 70,115 generated inputs, 69,430
unique inputs, 11,142 accepted rows, 63,364 inputs with at least one rejected
line, 6,273 of them rejecting a line after line 1. This number came from a
development invocation of the same fixed generator; the recorded run's log
carries the authoritative count and the full breakdown.

## The negative control

A green comparison is only evidence if the comparison can fail. The model has
22 named single-rule edits (`--list-mutants`): accept any column count, accept
an empty source or translation, ignore the duplicate key, accept an unknown
escape or a trailing backslash, accept an unknown `@` context, skip the
placeholder/ellipsis/template/plural checks, accept control characters or a
mid-row BOM, drop the file-BOM or CR strip, do not exempt `@id`, use 0-based
line numbers, do not skip `#` lines.

`--mutants` runs the full space once per edit and requires at least one
divergence each. The recorded run's mutation score is in its log; the gate
requires all 22 to be caught. A surviving mutant fails the run; the score is
measured, not asserted.

## Decision rule, fixed before the run

A divergence is a finding, not a prompt to edit the model until it agrees.

1. If the model is wrong, fix the model and re-run the whole space. The log is
   new evidence; the old one stays in git.
2. If the implementation is wrong, report it to the target. Do not narrow the
   model to hide it. The target is read, never modified.
3. If the model states a rule the format document does not imply, narrow the
   declared space and record why, or keep the rule as an explicit assumption.
   "The implementation does it" is not a source for the model.

This file does not state the result. The run log, the proof manifest and the
claim ledger do, and they are written after the run, not before it.

## What this does not prove

- Agreement is only over the declared vocabulary. Real catalog text is
  arbitrary Unicode; long lines, unusual combining sequences and catalogs
  larger than three rows are not exhausted.
- The model and the implementation were written by the same author. A shared
  misreading of `docs/catalog-format.md` is invisible to a differential check:
  both sides would be wrong together.
- It is a bounded differential check, not a proof of equivalence. The space is
  enumerated exhaustively *within the declared vocabulary*, and nowhere else.
- `read_catalog` is called directly. The target's file discovery, locale
  validation and tree checks (`check_tree`) are outside this model.
- `forms` is 1, 2 or 3. Arabic's six CLDR categories are not in the space.
- Duplicate detection is compared on catalogs of at most three rows.
- The 22 mutants are known edits. A high mutation score says the space is
  sensitive to those edits; it does not enumerate all possible bugs.
- The target is pinned by [`crosscheck/c02-row-model/TARGET`](../../crosscheck/c02-row-model/TARGET).
  A change to the target after the cited commit is caught by `claim_lint` L2
  (the artifact no longer matches its blob at the commit), not by this
  cross-check. Changing the pin is a declared dependency of the proof and
  triggers a re-run.
