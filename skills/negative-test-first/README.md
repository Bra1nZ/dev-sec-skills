[![Format: agent skill](https://img.shields.io/badge/format-SKILL.md-orange)](SKILL.md)
[![Discipline: negative test first](https://img.shields.io/badge/дисциплина-негатив%20тест%20первым-2ea44f)](SKILL.md)

Скилл для агентов-программистов: общая дисциплина тестирования любого
продукта, у которого есть заявления, обязанные выполняться. Бизнес-правила
(«нельзя списать больше, чем на счету»), инварианты данных («баланс равен
сумме движений»), переживаемость состояния («данные не теряются при
рестарте»), параллельная работа («не задвоить списание»), контракты API,
разграничение доступа и аудит — всё, где «фича работает» ничего не доказывает,
а доказывает только «нарушить не получилось».

Скилл вырос из реальной практики: разработки расширения разграничения доступа
для PostgreSQL, где каждый механизм защиты обязан иметь негативный тест, а
каждый сбежавший дефект превращается в именованный урок, который живёт в
комментариях кода и в тестах.

## Главная мысль

Требование считается покрытым, только когда тест показал: **нарушить не
получится**. Тест, который проверяет только счастливый путь, не доказывает
ничего о правиле. На каждое заявление — «списать больше баланса нельзя»,
«только роль X может писать в таблицу T», «данные переживают рестарт» —
должен существовать тест, который попытался это нарушить: на границе, за
границей, параллельно, через обходной путь — и не смог.

Обычный порядок обратный: сначала позитив («фича работает»), а негативы
«если останется время». Здесь наоборот: негатив пишется первым, позитив —
дешёвая половина. Безопасность — не отдельная тема, а самый острый случай
той же дисциплины.

## Что внутри

`SKILL.md` сжат до рабочего минимума: core rule, таблица «заявление →
обязательный негатив», workflow из девяти шагов, паттерны, антипаттерны и
security-раздел. Мотивация и история — в этом README, чтобы не тратить
контекст агента.

Ключевые механики:

- каждое требование парно с негативным тестом, а список заявлений становится
  индексом покрытия;
- классы входов перечисляются и проверяются по отдельности: пусто, один,
  много, на границе, за границей;
- после ожидаемого отказа проверяется, что мир не изменился;
- отказ классифицируется: **кто** отказал — наш код, платформа, драйвер;
- ветвление по платформам честное: «наша проверка — защита в глубину» вместо
  зелёного света ни за что;
- свидетельства проверяются в двух каналах: то, что умирает с транзакцией, и
  то, что её переживает;
- негативы повторяются после миграции на живых данных;
- пороги производительности выводятся из A/B-базлайна;
- тест проверяется на способность упасть: mutation/no-op, а не наличие файла.

## Установка

Скилл нейтрален к платформе агента — это `SKILL.md` с описанием принципов и
паттернов.

```bash
git clone <repo-url> dev-sec-skills
cp -r dev-sec-skills/skills/negative-test-first ~/.config/opencode/skills/
```

Для агентов, читающих скиллы из других мест, положите каталог туда, где агент
ищет скиллы. Скилл активируется сам, когда задача про план тестов для фичи или
продукта, тесты бизнес-правил и инвариантов, проверку покрытия негативами,
классификацию отказов или базлайны производительности.
